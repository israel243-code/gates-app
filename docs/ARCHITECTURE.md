# שערים – ארכיטקטורה ותוכנית "בלי שרת מרכזי" (אפשרות ג')

## היום (מצב רגיל)
טלפון → שולח מיקום כל ~3 שניות → השרת (isrnb.duckdns.org) מחשב מרחק / התקרבות → השרת פותח דרך Google Assistant בחשבון הגוגל של המשתמש.

## שלב 1 – "חישוב בטלפון" (קיים, ניסיוני, מתג בהגדרות)
- `LocalEngine.java`: מושך מהשרת רק הגדרות (`/st`: שערים מותרים, ברירות מחדל, הגדרות אישיות) פעם ב-10 דקות.
- מחשב בטלפון: בתוך הרדיוס + מתקרבים (המרחק קטן מהקודם ביותר מ-3 מ', עד 60 שניות אחורה) + זמן בין פתיחות.
- שולח לשרת רק `POST /open?t=… gate=<שם>&auto=1`. **המיקום לא יוצא מהטלפון.**
- השרת עדיין: מאמת את הקישור, בודק שבת / חג ומתג כללי, ופותח דרך הגוגל של המשתמש.

## שלב 2 – פתיחה ישירה מהטלפון (מתוכנן)
- `Opener` חדש: הטלפון שולח "open <gate>" ישר ל-Google Assistant (gRPC) עם התחברות גוגל בטלפון (Custom Tabs / AppAuth).
- דרישות: לקוח OAuth מסוג Android בפרויקט Google Cloud (SHA-1 של מפתח החתימה), הרשאת `assistant-sdk-prototype` – רגישה; לציבור רחב צריך אימות של גוגל.
- סיכון: ה-Assistant SDK לא רשמי לשליטה במכשירים, ועלול להשתנות.

## שלב 3 – בלי שרת בכלל (מתוכנן)
- הגדרות השערים (שם בגוגל הום, מיקום, רדיוס) נשמרות בטלפון; ייבוא / ייצוא כקובץ או קוד QR מבעל השערים.
- עדכוני אפליקציה: ממשיכים מ-GitHub Releases (או חנות).
- השרת נשאר רק לבעלים (בוט אישי), לא לאורחים.

## עקרונות שלא משתנים
- כל משתמש פותח רק דרך חשבון הגוגל שלו (אף פעם לא דרך חשבון של מישהו אחר).
- שידור ברקע רק כשמחובר בבלוטות' לרכב שהמשתמש בחר, או ידנית לזמן קבוע.
- בלי שבת / חג בפתיחה אוטומטית.
